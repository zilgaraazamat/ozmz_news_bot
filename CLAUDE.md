# OZMZ Football Astana

Telegram Mini App + бот для организации любительских матчей в Астане: запись на
игры, оплата, распределение по командам, статистика игроков, турниры.

## Стек

Намеренно минималистичный — **только стандартная библиотека Python**, без
фреймворков, ORM, сборщиков и npm.

- `bot.py` — точка входа. Поднимает HTTP-сервер в фоновом потоке и крутит
  long-polling Telegram + расписание контент-постов.
- `server.py` — только диспетчер: два словаря (POST/GET) мапят путь → метод,
  `Handler` собирается из миксинов в `routes/`.
- `routes/` — по миксину на предметную область (`games.py`, `tournaments.py`,
  `admin_games.py`, …).
- `storage/` — работа с SQLite. `_db.py` держит схему и миграции.
- `webapp/` — vanilla HTML/CSS/JS страницы Mini App, по файлу на экран.
- БД: SQLite на Railway Volume (`/data/roles.db`).

## Деплой

Railway, автодеплой из GitHub при `git push`. Ветка `main`.

Переменные окружения: `BOT_TOKEN`, `CHAT_ID`, `ADMIN_IDS`, `ANTHROPIC_API_KEY`,
`RAILWAY_PUBLIC_DOMAIN`.

## Архитектурные правила

Их нарушение уже приводило к поломкам, поэтому они не обсуждаются:

1. **Статистика игроков только через `get_player_stats()`** (`storage/player_stats.py`).
   Никогда не считать OVR, серии или голы отдельно в роутах или на фронтенде.
   OVR (`1 + игры//5 + MVP×1 + победы_в_турнирах×3`, голы в формулу не входят
   — `storage/ovr.py`) и недельная серия **никогда не хранятся** — всегда
   вычисляются на лету. Победа в турнире засчитывается только капитану
   команды-чемпиона (`get_tournament_win_counts()`, `storage/tournaments.py`)
   — у остальных игроков состава нет привязки к реальному `user_id`.

2. **`storage/__init__.py` реэкспортит всё публичное** и содержит `__all__`.
   Добавил функцию в модуль — обязательно добавь в оба места, иначе
   `ImportError` на Railway.

3. **Цены и суммы — только `storage/pricing.py`.** Поле `price` у игры это
   свободный текст («2500 ₸»); парсить его где-то ещё нельзя. Сумма записи
   считается **только на бэкенде** в момент записи и сохраняется в
   `game_signups.amount` — клиент сумму не присылает.

4. **Вместимость игры = `num_teams × players_per_team`** (`teams.game_capacity`).
   Поле `num_players` — только запасной вариант, если разбивка не задана.
   Бэкенд и фронтенд обязаны брать одно и то же число.

5. **В составы команд попадают только подтверждённые записи** (`status='confirmed'`).
   Оплата везде проходит цикл «оплатил → админ подтвердил».

6. **Турнирная таблица и чемпион нигде не хранятся** — считаются из сыгранных
   матчей (`storage/tournaments.py`). Чемпион = победитель матча с раундом
   ровно «Финал».

7. **`threading.Lock` нереентрантный.** Начисление XP всегда выполняется
   *после* основной транзакции, не внутри неё, иначе взаимоблокировка.

8. **Идентификация пользователя.** Бот подставляет `?uid=` в каждую ссылку;
   страницы читают ID сперва из URL, потому что `Telegram.WebApp.initDataUnsafe.user`
   ненадёжен на iOS.

9. **Миграции идемпотентны** — `ALTER TABLE` в `try/except sqlite3.OperationalError`.

## Дизайн Mini App

Тёмная тема в духе Telegram: фон `#0B0D10`, карточки `#181A1F`, акцент индиго
`#5E6AD2` / `#8B93F5`. Успех `#30D158`, ожидание `#E5A93C`, ошибка `#EC6A5E`.

Паттерны: Bottom Sheet со свайпом-вниз и кривой `cubic-bezier(.32,.72,0,1)`,
`HapticFeedback` на действия, липкие кнопки снизу с `env(safe-area-inset-bottom)`,
`tabular-nums` для чисел. Ориентиры: EA FC, FotMob, Sofascore, Linear.

Админка (`webapp/admin.html`) — наоборот, светлая SaaS-тема.

## Как со мной работать

- Отвечай и комментируй код **по-русски**.
- Нужен **готовый рабочий код**, а не объяснения и не советы «как можно было бы».
- **Минимальные точечные правки** существующих файлов; полное переписывание —
  только если я прямо прошу.
- Не оставляй TODO и заглушек. Если фича не реализована — честно скажи об этом,
  а не выдумывай данные.
- Переиспользуй существующие компоненты, хелперы и стили. Не плоди дубликаты.
- После правок прогоняй проверки (см. ниже) — молча ломать деплой нельзя.

## Проверки перед коммитом

```bash
# импорты и роуты — ловит ImportError, который валит Railway
python3 -c "
import bot, server
from server import Handler, POST_ROUTES, GET_ROUTES
assert all(hasattr(Handler, m) for m in list(POST_ROUTES.values()) + list(GET_ROUTES.values()))
from storage import init_db; init_db(); init_db()
print('OK')"

# синтаксис JS на страницах
node -e "
const fs=require('fs');
for (const f of fs.readdirSync('webapp').filter(x=>x.endsWith('.html'))) {
  const h=fs.readFileSync('webapp/'+f,'utf8');
  for (const b of (h.match(/<script>([\s\S]*?)<\/script>/g)||[])) {
    if (b.includes('telegram-web-app')) continue;
    new Function(b.replace(/<\/?script>/g,''));
  }
  console.log('OK', f);
}"
```
